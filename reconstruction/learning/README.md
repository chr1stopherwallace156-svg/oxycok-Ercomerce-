# Reusable reference learning

This extends the existing reconstruction campaign with a learning corpus and
content-addressed evidence. It does not replace Elektron's Failure Trap, RFL,
RLR, B3B, qualification owner or authority boundaries.

Read ELEKTRON_PROCESS_V1.json for the observed process and source pins. The
learning directory index covers 39 root RFL records, three preserved historical
variants and their collision audit. Full paths and blob identities distinguish
colliding historical IDs. Private source bodies are excluded. The process review
covers selected implementations and doctrine, not every Industrial branch or
all of its 9,233 files. Source passes do not qualify OXYCOK.

The reusable process is: pin subject and baseline; capture the original failure;
contain affected lineage; classify by mechanism; minimize and reproduce;
retrieve existing methods and exclusions; map systemic effects before repeated
repair; freeze the denominator; repair separately; attack with broken and
positive controls; freeze the semantic subject; request independent qualification;
record systemic learning and sibling dispositions; measure actual worker/consumer
use; review bounded inheritance and rollback; retain unresolved questions.
A local repair and repository learning are separate closure claims.

For a new repository or domain:

1. Run the immutable Git scanner against a full commit. Keep nested Git scopes
   and unreviewed mechanisms open. The scanner reads all blobs; lexical matches
   only navigate error, recovery, uncertainty, effect and test locations.
2. Copy TEMPLATE_V1.json into a draft outside the validated corpus. Fill it from
   actual evidence, not filename similarity, source labels or a prior pass.
3. Preserve runner outputs with `learning.preserve`; new observations receive new
   identities. Retain old FAIL and link the successor rather than overwriting it.
4. Bind the record to source paths/blob identities, applicability, exclusions,
   positive methods, hostile controls, consumer effects and remaining unknowns.
5. Audit the record set and verify custody. Audit exit 3 means OPEN, exit 2 means
   invalid; no command in this tool promotes a runtime default or releases a trap.
6. Retrieve candidate worker context with declared facts. Missing context is
   NEEDS_CONTEXT; an exclusion wins; a matching candidate is REVIEW_REQUIRED.
   Matching never supplies permission, proof of truth or independent qualification.

```sh
python3 -B scripts/reconstruction/learning.py scan --root /read-only/reference --commit FULL_40_HEX_COMMIT --repository owner/project --output-dir /separate/evidence
python3 -B scripts/reconstruction/learning.py audit --inventory INVENTORY_JSON --records RECORDS_JSON
python3 -B scripts/reconstruction/learning.py retrieve --inventory INVENTORY_JSON --records RECORDS_JSON --fact resource-cleanup --fact primary-error
python3 -B scripts/reconstruction/learning.py verify-custody --root . --index reconstruction/subjects/rea/learning/CUSTODY_V1.json
```

The complete REA application is the first source subject. See its learning
README for tested mechanisms, raw red evidence, positive methods and unreviewed
scope. Worker-written diagnostics and tests remain implementer evidence. The
actual pinned Elektron SystemicFailureAnalysis owner also evaluated the new
failure record's twelve-field presence; that result is structural, not semantic
or independent qualification. Do not interpret it as full Failure Trap execution.

Repeat retrieval after relevant evidence changes. Demote a contradicted future
binding while retaining its history. Unknown families stay unknown; historical
failures are not automatically current defects; expected fail-closed behavior
is not automatically a blocker. Repetition on one restricted host is not an
independent fresh qualification failure count.
